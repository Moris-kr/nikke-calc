# 설정 공유 서버

전투 조건(보스)과 조합 설정을 **이름 붙여 올리고, 목록으로 받고, 엄지로 평가하는** 곳이다.
사이트는 정적 호스팅(GitHub Pages)이라 저장할 곳이 없어 이 Worker가 그 자리를 맡는다.

`worker/`(블라블라링크 프록시)와 나눠 뒀다. 저쪽은 남의 계정을 대신 조회하느라 로그인 세션
비밀이 필요하고 이쪽은 필요 없다 — 하나로 합치면 공유 기능을 고칠 때마다 그 비밀을 쥔
Worker를 다시 배포하게 된다.

## 여기서 하지 않는 일

게임 데이터를 해석하지 않는다. 저장되는 것은 **사이트가 만든 공유 코드 문자열**과 사람이 붙인
이름뿐이고, 그 코드가 무슨 뜻인지 — 몇 초짜리 전투인지, 누가 편성됐는지 — 는 브라우저만 안다.
목록에 함께 뜨는 «설명»도 사이트가 만들어 보낸다. 그래서 게임이 바뀌어도 이 Worker를 다시
배포할 일이 없다.

## 배포

```bash
cd worker-share
npx wrangler login
npx wrangler kv namespace create SHARE   # 나온 id를 wrangler.toml에 붙여넣는다
npx wrangler deploy
```

배포하면 `https://nikke-calc-share.<계정>.workers.dev` 주소가 나온다. 그 주소를
`site/.env.production`의 `VITE_SHARE_API`에 적는다.

```
VITE_SHARE_API=https://nikke-calc-share.<계정>.workers.dev
```

값이 비어 있으면 사이트는 공유 모달에 **서버 탭을 아예 그리지 않는다** — 코드 주고받기만
남는다. 주소 없이 부르면 반드시 실패하므로, 탭을 만들어 두는 쪽이 더 헷갈린다.

`ALLOWED_ORIGINS`에 없는 오리진에는 CORS 헤더를 주지 않는다. 사이트 주소가 바뀌면 여기도
같이 고쳐야 한다.

## API

| 요청 | 하는 일 |
|---|---|
| `GET /list?kind=boss\|squad\|union` | 목록 + **이 IP가 이미 누른 표**(`mine`) |
| `POST /upload` | `{kind, name, by, auto, code}` → 새 항목(같은 코드가 있으면 그 항목) |
| `POST /vote` | `{kind, id, value: 1\|-1\|0}` → 바뀐 표 수 |
| `POST /apply` | `{kind, id}` → 적용 횟수. **IP당 한 번만** 오르고 취소가 없다 |

이름은 필수, 업로더(`by`)는 비우면 빈 문자열로 남고 사이트가 «익명»으로 적는다. 코드는 종류에
맞는 접두사(`NK3-` 전투 조건 · `NK2-` 조합 · `NK4-` 유니온 레이드 판)여야 받는다.

`union`은 유니온 레이드 판 하나를 통째로 담은 것이다 — 보스 다섯의 이름·조건과 각 칸의 덱까지
한 코드에 들어 있다. **유니온원 명단은 담기지 않는다**: 저장되는 것은 다른 종류와 똑같이 코드
문자열과 이름뿐이고, 닉네임·openid는 애초에 코드에 실리지 않는다.

종류를 새로 들일 때는 `KINDS`에 한 줄 더하고 **다시 배포해야 한다** — 모르는 종류는 400으로
거절되고, 사이트에서는 목록 자리에 «알 수 없는 공유 종류입니다»가 뜬다.

## 한 표의 뜻

투표자는 **IP를 소금과 함께 해시한 값**으로 가른다. 원문 IP는 저장하지 않는다. 한 항목에 한
표고, 같은 것을 다시 누르면 취소, 반대쪽을 누르면 갈아탄다.

한계를 분명히 알고 쓴다 — 같은 공유기·같은 캐리어를 쓰면 여러 사람이 한 표로 묶이고, IP가
바뀌면 같은 사람이 다시 누를 수 있다. 정확한 신원이 아니라 «한 사람이 연달아 밀어 올리는 것»만
막는 장치다. `VOTE_SALT`를 바꾸면 «누가 이미 눌렀나»가 전부 초기화된다(표 수 자체는 남는다).

## KV에 들어가는 것

| 키 | 값 |
|---|---|
| `catalog:<kind>` | 항목 전부(`{items:[…]}`) — 목록 한 번에 한 번 읽는다 |
| `votes:<kind>:<해시>` | 그 사람이 누른 표 `{항목id: 1\|-1}` |
| `uses:<kind>:<해시>` | 그 사람이 이미 적용해 본 항목 `{항목id: 1}` |
| `rate:<해시>` | 하루 업로드 수 |

목록을 키 하나에 모아 두면 조회가 읽기 한 번으로 끝나지만, **동시에 들어온 투표는 서로를 덮을
수 있다**(읽고-고쳐-쓰기라서). 수백 명 규모에서 표 하나가 가끔 유실되는 정도라 그대로 두었다.
정확한 집계가 필요해지면 Durable Object로 옮기는 것이 다음 수순이다.

한 종류에 400개까지 받고, 그 뒤 업로드는 거절한다. IP당 하루 20개까지 올릴 수 있다.
지우는 기능은 없다 — 지금은 `npx wrangler kv key delete --binding SHARE catalog:boss`처럼
손으로 지운다.

## 지금 보고 있는 사람 수 (`POST /presence`)

`{ "id": "탭마다 만든 무작위 문자열" }`을 보내면 `{ "online": n }`을 돌려준다. 45초마다
한 번씩 인사하고, 마지막 인사로부터 100초가 지나면 나간 것으로 친다.

**KV를 쓰지 않는다.** 인사 한 번이 쓰기 한 번이면 무료 한도(하루 1,000회)를 몇십 명이
몇 분 머무는 것만으로 넘긴다. Durable Object(`Presence`) 하나에 모여 **메모리에서** 세므로
저장 쓰기가 0이다. 방은 `global` 하나뿐이다 — 모두가 같은 수를 봐야 하니 한곳에 모은다.

오래 조용하면 객체가 잠들어 숫자가 0부터 다시 쌓인다. 사람들이 다음 인사를 보내는 45초
안에 제자리로 돌아오므로 그대로 둔다. 정확한 동시접속이 아니라 «지금 대충 몇 명»이다.

보내는 표식은 **탭마다 새로 만드는 난수**다. 사람을 가려내지 않으므로 같은 사람이 두 탭을
열면 둘로 센다 — 방문자를 추적하지 않는 쪽을 택한 결과다.
