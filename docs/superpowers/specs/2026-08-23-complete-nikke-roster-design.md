# 전체 니케 등록 설계

## 목표

현재 계산 카탈로그 86명과 `scraper/nikke_scraped.json`의 출시 캐릭터 199명 사이의 차집합 113명을 모두 등록한다. 10명씩 완성·검증·배포하고 마지막 배치는 3명으로 구성한다.

## 범위와 원칙

- 기존 86명은 재등록하지 않는다.
- 등록 순서는 기존 `context/PARSING-CHARS.md`의 `예정` 7명, 나머지 SSR, SR, R 순이다. 같은 등급에서는 `scraper/nikke_scraped.json`의 정본 순서를 따른다.
- 각 캐릭터는 `.agent/skills/char-add/SKILL.md`의 단계 1 → 2 → 3 → 4를 순서대로 수행한다.
- 사용자의 이번 지시에 따라 단계별 사용자 승인 대기는 생략한다. 해석 충돌이나 특수 메커니즘도 합리적인 명시적 가정으로 계속 진행하고 배치 보고에 남긴다.
- 캐릭터별 예외를 공통 계산식에 이름으로 하드코딩하지 않는다. 기존 효과 시스템, 파싱 데이터 또는 일반화된 메커니즘으로 표현한다.
- 블라블라링크 니케 도감의 스킬 설명과 수치를 캐릭터별로 대조한다. 저장소에 반영되는 원문 정본은 계속 `scraper/nikke_scraped.json`이다.
- 신규 동작은 실패 테스트를 먼저 작성하고 실제 실패 원인을 확인한 뒤 최소 구현한다.

## 캐릭터별 데이터 흐름

각 캐릭터마다 다음 흐름을 독립적으로 유지한다.

1. 블라블라링크 상세 화면과 `nikke_scraped.json`의 무기·버스트·스킬 문구·레벨별 값을 대조한다.
2. `context/scenarios/<정식 명칭>.md`에 초안 시나리오, 검증 스쿼드, 타임라인과 해석 가정을 기록한다.
3. `data/parsed_skills.json`에 효과 단위 파싱을 추가하고 `context/PARSING-CHARS.md`의 상태를 갱신한다.
4. 시나리오를 보강 모드로 바꾸고 stat·트리거·대상·실행 순서·스택과 지속시간을 명시한다.
5. 기존 엔진으로 표현되지 않는 동작은 일반화 가능한 stat/condition/timing으로 추가하고 회귀 테스트를 먼저 만든다.
6. 캐릭터가 실제 카탈로그와 시뮬레이션에 진입하는지 검증한다.

## 특수 케이스와 후속 검증

`context/CHAR-SPECIAL-CASES.md`를 테스트 색인으로 사용한다. 계산 규칙이나 수치를 복제하지 않고 각 캐릭터 시나리오의 정본 절을 링크한다. 각 행은 다음을 가진다.

- 캐릭터 정식 명칭과 배치 번호
- 특수 메커니즘 한 줄 요약
- 위험 유형: 실행 순서, 스택, 모드 전환, 소환체, 무기 변경, 조건 판정, 수치 출처 또는 실측 필요
- 자동 테스트 위치와 검증 상태
- `확인 완료`, `가정 적용`, `추가 실측 필요` 중 하나의 상태

특수 케이스 발견은 배치를 중단시키지 않는다. 가능한 해석으로 구현하고 테스트하며, 확정 근거가 부족하면 `가정 적용` 또는 `추가 실측 필요`로 배포 보고에 노출한다. 명백히 잘못된 계산을 알면서 통과시키지는 않는다.

## 검증과 배포 게이트

각 배치는 다음을 모두 통과해야 한다.

1. 캐릭터별 시나리오 체크리스트와 신규 단위/회귀 테스트
2. `cd site && npx tsc --noEmit`
3. `cd site && npm test -- --run`
4. `python -m context.doclint`
5. `python -m context.snapshot`
6. `cd site && npm run build`
7. `python -m unittest calculator.test_customization`
8. `python calculator/damage.py`
9. 배치 시작 시점 대비 카탈로그가 정확히 10명 증가했는지 확인한다. 마지막 배치는 3명 증가해야 한다.
10. `master`에 커밋하고 `origin/master`로 푸시한 뒤 GitHub Pages 성공과 배포 사이트 반영을 확인한다.

배포 보고에는 신규 명단, 특수 케이스 상태, 테스트 결과, 커밋 해시와 배포 주소를 포함한다.

## 실패 처리

- 문서/파싱/동작 불일치는 시나리오에 대안 해석과 선택 근거를 기록하고 계속 진행한다.
- 자동 검증 실패는 배포하지 않고 해당 배치 안에서 수정한다.
- 블라블라링크가 일시적으로 열리지 않으면 로컬 정본으로 진행하되 배포 보고에 대조 미완료를 표시하고 후속 확인 대상으로 남긴다.
- 컬래버 및 저등급 캐릭터도 제외하지 않는다.
