# 듀얼 우월 코드·애장품·캐릭터 컨트롤 상세 설정 설계

## 목표

- 라피 : 레드 후드와 슈가처럼 기본 코드 외의 적에게도 우월 코드 대미지를 적용하는 캐릭터를 데이터 기반으로 계산한다.
- 애장품이 있는 캐릭터는 별도 단계 선택 없이 애장품 3단계를 항상 적용하고, 이 규칙을 상세 설정에 명시한다.
- 톡톡이, 홀드, 재장전, 버스트 엄폐 컨트롤을 각 캐릭터 상세 설정에서 켜고 끌 수 있게 한다.
- 기존 오버로드 상세 설정에 정본 장비 스킬 표의 오버로드 옵션 9종 전체를 추가한다.

## 데이터 정본과 범위

- 캐릭터 스킬 원문은 `scraper/nikke_scraped.json`을 정본으로 사용한다.
- 현재 원문에서 기본 코드 외 우월 판정이 확인되는 캐릭터는 다음 둘이다.
  - 라피 : 레드 후드: 기본 작열 + 전격 코드 적 우월
  - 슈가: 기본 철갑 + 애장품 1단계 효과로 작열 코드 적 우월
- 슈가는 애장품 3단계 기준으로 스킬 1·2·버스트 전체를 다시 파싱한다. 3단계에는 1·2단계 개선 효과가 누적된다.
- 컨트롤 의미와 권장값은 `context/CONTROL.md`, 캐릭터별 자동 추천은 `data/char_defaults.json`을 정본으로 삼는다.
- 오버로드 차지 속도 수치 범위는 `data/base_stat_tables/equipment_skills.json`의 `charge_speed_pct`를 사용한다.

## 듀얼 우월 코드 모델

캐릭터의 `element_code`는 단일 기본 코드로 유지한다. 아군 대상 선정과 코드 조건 스킬은 이 기본 코드만 사용한다. 추가 우월 코드는 공격 시 적 코드와의 우월 판정에만 더한다.

파싱된 효과 `element_code_override`에 구조화된 `target_code`를 저장한다. 활성 효과의 `target_code`가 현재 적 코드와 일치하면 해당 공격을 우월 공격으로 처리한다. 캐릭터 이름 하드코딩이나 한국어 메모 재파싱은 하지 않는다.

이 방식으로 지속시간·조건이 있는 미래의 추가 우월 효과도 같은 경로로 처리한다. 정본 원문에 같은 문구가 새로 생겼는데 파싱 결과가 누락되면 실패하는 회귀 테스트를 둔다.

## 애장품 표시와 적용

애장품 보유 캐릭터는 계산기에서 항상 애장품 3단계를 사용한다. 상세 설정에 다음 문구를 표시한다.

> 애장품 보유 캐릭터는 반드시 애장품 3단계로 적용합니다.

가능하면 애장품 이름도 함께 표시한다. 애장품 단계 선택기는 만들지 않는다.

## 캐릭터별 컨트롤 상세 설정

컨트롤은 적 속성이 아니라 조작 중인 캐릭터의 행동이므로 모두 캐릭터 상세 설정에 둔다. 적 설정에는 기존 적 코드, 코어, 파츠처럼 실제 적 상태만 둔다.

상세 설정의 컨트롤 모드는 다음 두 상태를 지원한다.

1. 추천 자동 적용: 기존 캐릭터 기본값과 조합 조건부 규칙을 그대로 사용한다.
2. 직접 설정: 해당 캐릭터의 컨트롤을 사용자가 선택한 값으로 통째로 대체한다. 모든 토글을 끄면 컨트롤 없음이 된다.

직접 설정에서 제공하는 항목은 다음과 같다.

- 톡톡이: SR/RL에만 표시한다. 켜면 정본 권장값인 초당 3.6발, 릴리즈 0.03초를 사용한다.
- 홀드: SR/RL에만 표시한다. 캐릭터 권장 규칙이 있으면 그 정책과 리드값을 사용한다. 일반 설정은 `own_full_burst` 정책과 0.5초 리드를 기본으로 한다.
- 재장전 컨트롤: 모든 무기에 표시한다. `풀버스트 종료 전 재장전`과 `풀버스트 진입 재장전` 정책 중 하나를 고르게 하며 각각 정본 기본 리드/마진을 사용한다.
- 버스트 엄폐 컨트롤: 모든 무기에 표시한다. 켜면 본인 풀버스트 동안 엄폐하는 정책을 사용한다.

동시에 여러 캐릭터에 수동 컨트롤을 켜면 실제 한 명 조작보다 유리한 상한이 될 수 있으므로 상세 설정과 결과에 경고를 표시한다. 엔진은 기존처럼 계산을 허용한다.

기존 재귀 병합에서는 빈 `control`로 자동 추천을 지울 수 없다. 브라우저 요청의 컨트롤이 명시된 경우에는 캐릭터 레이어 병합 후 `control`을 재귀 병합하지 않고 완전히 교체한다. 필드 미지정은 추천 자동, 빈 객체는 컨트롤 없음이라는 계약을 사용한다.

## 오버로드 옵션 전체 지원

오버로드 정식 필드에 `data/base_stat_tables/equipment_skills.json`의 9종을 모두 제공한다.

- 공격력 `atk_pct`
- 방어력 `def_pct`
- 우월 코드 대미지 `element_bonus`
- 최대 장탄수 `max_ammo_pct`
- 크리티컬 확률 `crit_rate`
- 크리티컬 대미지 `crit_dmg`
- 차지 속도 `charge_speed_pct`
- 차지 대미지 `charge_dmg_pct`
- 명중률 `accuracy_pct`

모든 캐릭터에게 같은 9종 입력란을 표시한다. 차지 속도와 차지 대미지는 비차지 무기에서도 입력할 수 있지만 현재 무기로는 효과가 없다는 안내를 붙인다. 값은 기존 `equip_skills` 경로로 들어가며 스킬 버프와 같은 계산식에 합산된다. 기본값은 현재 장비 설정값을 그대로 내보내고, 브라우저·Python 검증 모두 동일한 허용 범위를 사용한다.

## 사용자 흐름

캐릭터 카드에서 상세 설정을 켜면 다음 순서로 보인다.

1. 돌파·코어 강화와 최대 호감도
2. 스킬 레벨과 애장품 3단계 안내
3. 오버로드 옵션 9종 전체
4. 큐브
5. 컨트롤(추천 자동 / 직접 설정과 적용 가능한 토글)
6. 기존 고급 수치 설정

요약 줄에는 성장 단계, 주요 오버로드 수치, 큐브와 함께 컨트롤이 추천 자동인지 직접 설정인지 짧게 표시한다.

## 검증

- 라피 : 레드 후드가 풍압(기본 작열 우월)과 전격 적 모두에서 우월 대미지를 받고 다른 코드에는 받지 않는지 확인한다.
- 슈가가 애장품 3단계 스킬 전체를 사용하며 전격(기본 철갑 우월)과 작열 적 모두에서 우월 대미지를 받는지 확인한다.
- 추가 우월 코드가 아군 코드 대상 선정에는 영향을 주지 않는지 확인한다.
- 추천 자동, 직접 설정, 컨트롤 없음이 엔진까지 정확히 전달되는지 확인한다.
- 무기별 토글 노출, 각 정책의 요청 직렬화, 잘못된 컨트롤 요청 거부를 브라우저와 Python 양쪽에서 확인한다.
- 오버로드 9종이 모두 요청과 엔진에 연결되는지 확인한다. 특히 차지 속도는 차지 시간을 줄이고, 차지 대미지는 차지 공격 대미지만 높이며, 비차지 무기에서는 두 값이 결과에 영향을 주지 않는지 확인한다.
- 기존 Python 회귀, 웹 단위 테스트, 빌드, Pyodide 연동 테스트, 스냅샷과 문서 린트를 모두 실행한다.
