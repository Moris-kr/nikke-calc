# 오버로드 육성·모듈 분석 모델 (2026-09-19)

## 입력과 출처

현재 4부위 × 3줄의 효과·레벨과 현재 잠금 상태가 필요하다. 효과 합계만으로 줄 배치나 잠금을 추측하지 않는다. 잠금은 연동 정보에 없으므로 사용자가 직접 체크한다. 최초 장비 개조와 미장착 장비의 개조 비용은 제외한다. 모듈 분석은 각 부위 서로 다른 효과 3줄, 최종 Lv.15를 대상으로 한다. 12줄 미만 목표의 전투 비교는 가능하지만 모듈 분석은 제외 사유를 표시한다.

- 효과 가중치: 우월·공격력·크리티컬 대미지·방어력 각 10%, 장탄·명중·차지 대미지·차지 속도·크리티컬 확률 각 12%.
- 슬롯 등장: 1/2/3번 100%/50%/30%. 각 슬롯은 독립적으로 등장하며, 중복 효과는 배제하고 남은 효과의 가중치를 재정규화하는 모델이다. 잠긴 효과는 모든 슬롯의 추첨에서 제외한다.
- 레벨: 1~5 각 12%, 6~10 각 7%, 11~15 각 1%.
- 2026-09-19 사용자 확인: 크확 효과 등장 12%, 크댐 효과 등장 10%. 첫 잠금 1모듈, 둘째 추가 잠금 2모듈. 변경은 무잠금/1잠금/2잠금 각각 1/2/3모듈. 해제 후 다시 잠그면 새 잠금 비용을 낸다. 같은 효과·수치는 다른 수치가 나올 때까지 무료 재추첨.
- 공개 확률 전사 자료: https://cheonjang.com/nikke/overload (2026-07-13 기준; 잠금 비용은 현재와 달라 사용하지 않음).
- 변경 공지 전재: https://nikke.gg/september-17-patch-notes/ (2026-09-17 동일 결과 재추첨·잠금 변경 안내).
- https://nikkelab.com/custom-modules 는 9월 중순 변경 미반영을 명시한다. 이 사이트의 계산 결과를 검증 기준으로 쓰지 않는다.

공식 공시 원본을 직접 확보한 것으로 표시하지 않는다. 서로 충돌하던 크확/크댐 확률과 신규 잠금/재추첨 규칙은 사용자 확인을 적용했다. 다른 기본 확률은 공개 전사표 기반 모델이다. 출처가 바뀌면 모델 ID와 계산 프로그램을 함께 변경한다.

## 목표 구성

효과별 목표 줄 수 0~4, 합계 0~12. 줄 수를 변경하면 부위별 목표에 즉시 반영한다. 최대 12줄을 넘는 변경은 취소하고 안내한다. 전체 타협 조합을 모두 계산하는 비용을 피하기 위해 타협 옵션과 적용 버튼은 제거했다. 실제 전투·확률 계산은 계산하기 버튼에서만 시작한다. 직접 부위별 옵션을 편집할 수도 있다.

배치는 효과→부위 효과(용량1)→슬롯의 최소 비용 흐름으로 구한다. 현재 효과 유지 비용0, 변경 비용1을 사용한다. 이는 변경 슬롯 수 최소 배치이며 모듈 비용 최적 배치가 아니다. 모듈 분석에서 각 부위 효과 집합의 6배치를 다시 비교한다. 전체 효과 합은 동일하므로 전투 수치는 배치 변경으로 달라지지 않는다.

## 기대값 알고리즘

각 부위 6배치 × 6완성 순서 × 2정책(72후보).

1. 줄 완성 우선: 목표 줄의 효과를 찾고 Lv.15까지 만든 다음 잠근다. 나머지 목표가 이미 완성됐으면 마지막 잠금을 생략한다.
2. 효과 우선: 목표 효과를 순서대로 찾으며 잠근다. 세 효과가 맞으면 Lv.15 미만 잠금을 해제한다. Lv.15 줄만 잠그고, 새 Lv.15가 하나 이상 생긴 수치 결과만 채택하며 반복한다.

실패한 결과는 채택하지 않는다. 이미 목표에 맞는 효과·수치 변경은 생략한다. 기존 잠금 중 해당 정책에서 보존할 수 있는 것은 재사용한다. 해제·재잠금 비용을 포함한다.

- 효과 성공 확률 p: 잠금 상태별 가능한 효과 결과를 전부 열거하여 구한다. 슬롯 등장과 중복 배제의 조건부 확률을 곱하고 목표 줄이 맞는 결과를 합산한다.
- 실패 시 현재 상태를 유지하므로 성공까지 평균 변경 횟수는 1/p, 변경 비용은 (1+잠금 수)/p.
- 현재 레벨 k에서 Lv.15까지 수치 변경: k<15이면 p=0.01/(1-w[k]). 같은 수치가 나올 수 없도록 재정규화한 값이다. 기대 비용은 (1+잠금 수)*(1-w[k])/0.01.
- 효과 우선 정책의 여러 미완성 줄: 하나 이상 성공할 확률은 1-Π(1-p_i). 성공한 줄 집합의 조건부 분포도 열거한다.
- 잠금 비용은 첫 추가1, 둘째 추가2를 별도로 누적한다.

반복 실패 자체를 시뮬레이션하지 않고 위 기대값을 정확히 적분한다. 성공한 전체 장비 결과에서 다른 미잠금 줄이 어떻게 바뀌는지만 고정 시드로 표본 추출한다(Rao–Blackwell 방식). 후보당 96표본으로 전략을 선택하고, 독립 시드 4000표본으로 선택한 전략을 다시 평가한다. 결과는 평균 잠금 비용, 평균 변경 비용, 합계, 평균 추정의 근사 95% 오차(1.96*s/√n)를 표시한다. 부위 오차 합은 보수적으로 더한다. 이는 실제 재화 소모의 95% 구간이 아니다.

**제한:** 선택한 전략의 기대값 추정이며 모든 행동·타협·부위 배치의 전역 최적해가 아니다. 후보 선택 자체의 불확실성은 오차 막대에 포함되지 않는다. 실제 평균이 비슷한 전략의 우열은 확정하지 않는다. 표본 오차에는 게임 확률 모델 오차가 포함되지 않는다.

## 가성비

같은 전투에서 해당 니케의 오버로드만 목표값으로 바꾼 덱 총딜 증가량 / 모듈 기대값으로 정렬한다. 돌파·스킬·소장품·장비 강화로 얻는 이득을 분자에 섞지 않는다. 모듈0은 이미 달성으로 표시하며 무한 가성비를 만들지 않는다. 음수 이득은 그대로 표시한다. 각 후보는 독립 비교이고 합산하지 않는다.

## 외부 계산 / MCP

프롬프트는 같은 TypeScript 모듈을 빌드한 순수 Node.js 프로그램과 확률 입력, 버전 고정 공개 Python 엔진 및 전투 요청을 포함한다. 계정 ID·사진·대화는 포함하지 않지만 계산 대상 육성·편성·전투 정보는 포함한다. 자동 업로드하지 않는다. Node.js로 모듈 결과를 만들고 Python으로 기본 비교 전투를 계산해 하나의 결과 JSON으로 반환한다. 다운로드가 막힌 실행 환경은 사용자가 공개 엔진 ZIP을 첨부할 수 있다. 코드 실행이 없으면 추측 대신 중단하도록 안내한다.

export_overload_plan → get_browser_result → AI 자체 코드 실행 → import_overload_plan_result → get_browser_result. MCP는 입력과 결과만 중계하며 Render에서 무거운 계산을 하지 않는다. 추가 덱 내 우선순위 버튼은 브라우저 계산이다.

요청 UUID·모델·엔진 버전·전체 작업 ID·목표·표본 수·합계·유한수·편성 대미지 합계를 검증한다. 외부 코드나 HTML을 실행하지 않는다. 검증은 실제 실행을 증명하지 않으므로 외부 결과는 항상 미검증 표시한다. 목표/잠금 변경 시 이전 외부 결과를 무효화한다.

## 커스텀 락 키와 비용 분류 (2026-09-19 추가)

잠금 재화를 모듈 또는 커스텀 락 키로 선택한다. 키 방식은 기존 모듈 잠금을 모두 해제한 뒤 키만 사용하는 비교이며 혼합 잠금이나 키 보유량 제한은 다루지 않는다. 키 잠금은 변경 1회 후 해제되므로 실패 결과를 버리더라도 매번 다시 지불한다. 첫 줄 20개, 둘째 줄 추가 30개(두 줄 합계 50개). 변경 모듈은 무잠금/1줄/2줄 각각 1/2/3개다. 이 규칙은 사용자 확인을 적용했다.

성공 확률 p인 변경 단계에서 키 기대 소모는 (0/20/50)/p, 변경 모듈은 (1/2/3)/p다. 키 방식의 모듈 잠금 비용은 0이다. 키와 모듈을 환산하거나 합산하지 않는다. 전략은 모듈 기대값으로 선택하므로 키 소모 최적화를 보장하지 않으며 모듈당 딜에도 키 가치는 포함하지 않는다.

반환값 effect는 효과변경 모듈, value는 Lv.15 수치변경 모듈, lock은 잠금 모듈, keys는 별도 락 키다. change=effect+value, total=effect+value+lock. 화면과 이미지 보고서에 목표 12줄 찾기 / 수치작 / 잠금으로 구분한다. 효과변경으로 우연히 얻는 수치는 효과변경 비용에 포함된다. 줄 완성 우선 전략은 단계가 섞이므로 '12줄 찾기'는 선택한 전체 전략의 효과변경 비용이며 효과만 먼저 완성하는 독립 목표의 최소비용이 아니다. 이미 목표 효과가 있으면 효과변경 설명을 빼고 필요한 수치작·보호 안내만 표시한다.

외부 계산 모델은 `2026-09-19-lock-keys-v2`다. 재화 변경 시 내보낸 요청과 이전 결과를 무효화한다. 외부 결과의 재화 종류와 비용 분류 합계를 검증한다.
